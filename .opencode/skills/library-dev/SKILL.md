# MapICGC GL JS library development

Use this skill when a task touches `src/` (the browser library), its public API,
controls, constants, or `test/vitest/`.

## Workflow

1. Read `AGENTS.md` first.
2. Locate the closest existing implementation:
   - `src/map/Map.js` — the wrapper class. It owns `this.map`, the underlying
     `maplibregl.Map`, and delegates ~150 methods. Put new public methods next
     to related ones, not in a new file.
   - `src/controls/` — controls added through `addControl` or dedicated helpers.
   - `src/plugins/` — `CompareMaps` and the bundled geocoder.
   - `src/territorial/` — territorial API search and info panel.
3. Decide whether data belongs in code or config:
   - Styles, terrains, layers and default options normally come from the remote
     ICGC config. For the offline fallback, edit `src/mapicgc-config.json`.
   - `src/config.js`, `src/configNode.js`, `src/config-out.js` and
     `src/constants/{Styles,Terrains,Layers}.js` are generated by
     `npm run setConfig`. Do not hand-edit them unless the change is explicitly
     about the generated output.
4. Implement with JSDoc on every new public method (`@param`, `@returns`), in
   English. This feeds `docu_Map.md` and the MCP API reference.
5. Export anything consumers must import from `src/index.js`. Keep the UMD
   global name `mapicgcgl`.
6. Add tests in `test/vitest/MapFunctions.test.js` (Map API), `Config.test.js`
   (config) or a new focused suite. Mock remote calls; never depend on ICGC
   services being reachable.
7. Run `npx vitest run <file>` while iterating, then `npm run build`.
8. Add a `CHANGELOG.md` entry for user-visible changes.

## Pitfalls

- Do not remove the `setWorkerUrl()` call in `src/index.js`; without it
  `new maplibregl.Map()` hangs waiting for the worker and `load` never fires.
- Keep a single `maplibre-gl` instance. `vite.config.mjs` relies on
  `dedupe: ['maplibre-gl']`; importing through a second path can create two
  incompatible `Map` classes.
- `Map`'s constructor is effectively async: it loads config in a promise and
  only then calls `initTheMap`. Tests must wait for the map/`load` event or mock
  `Config.getConfigICGC`.
- Style handling has special branches (`RELIEF`, raster URLs, object styles).
  Check all branches when changing `initTheMap` or `setStyle`.
- `dist/` is generated; never commit build output.
